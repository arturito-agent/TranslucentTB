# Synthetic native validation evidence

These files record functional cases and separate latency trials. Resource
benchmarks are still in progress. All content was
generated by the repository's synthetic fixtures. Native functional and latency
evidence comes from the isolated Windows VM; the CI harness receipt described
below comes from a separate hosted Windows runner.
No private application data, authentication or host paths are included.

See [environment and limitations](../dynamic-validation.md) before interpreting
the results. A passing color row does not verify glyph contrast or every state.

`functional-*.csv` compares the expected color, worker's confirmed RGB and a
physical pixel on the real taskbar. RGB values are decimal 0xRRGGBB. `captures`
in these early fixtures means sampling **attempts**, not completed DXGI frames.
`run_length` is physical steps, not the total frequency of a color. Rectangle
right/bottom bounds are exclusive. `-125` records 125% scale; other files use
100%. The reference display remains 1280x800.

`states-*.csv` records Desktop Dynamic / Maximized Clear and a visible-window
title rule that alternates Dynamic/Clear. Attempts must remain unchanged during
the measured part of each Clear stage and advance during Dynamic. Sizable
window frames can be unreliable input: before any confirmed color, Dynamic
must render the known fallback RGB 32,48,64. This is checked explicitly rather
than assuming the client background extends through a native window frame.

`display-off-*.json` records the actual display-off command and subsequent
console-key wake. Off-state timer=0, paused=1 and unchanged attempts are checked;
after waking, timer=1, paused=0 and increasing attempts are required.

QPC ticks and frequency are the Windows monotonic clock, shared across processes.
Do not interpret them as UTC. Short functional stages do not establish CPU/RAM, stability or energy results.
The focus-latency CSVs and focus-latency-a1b0.json use 30 jittered trials per
backend, a 50ms observer and nearest-rank p95. They include the DXGI maximum
outlier and identify the exact application revision and geometry.

`refresh-race-a1b0.json` is a negative control: bounded overlapping forced-refresh
and sent timer messages leave the classic-taskbar sampler stopped while not
paused. It records a reproduced defect, not a passing result or resource trial.
`refresh-race-right-*-b464-r*.json` records three fixed-revision trials per
backend, each with active timers and increasing attempts after the overlap.
`functional-right-*-b464.csv` records the six color cases per backend after that
fix. These short tests do not establish resource budgets or prolonged stability.

`fixture-check-ci-1851.json` records Windows PowerShell compile/protocol/lifecycle
checks on GitHub-hosted Windows Server 2025. Uniform has zero animation ticks;
Changing and Interaction produce repeated paints at a nominal33ms timer interval.
Counts describe callbacks, not monitor presentation. This checks test tooling
only and establishes no application resource result or local VM preflight.
